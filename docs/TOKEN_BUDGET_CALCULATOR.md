# Acme Corp Internal Knowledge Base Assistant — Token Budget Calculator

## 1. Purpose

This document estimates the computational and financial requirements of running the Acme Corp Internal Knowledge Base Assistant. It compares cloud-based LLM usage with local inference through Ollama.

## 2. Understanding Tokens

A token is a unit of text processed by a Large Language Model.

There are two major token categories:

- **Input Tokens:** Text sent to the model, including system prompts, user questions and retrieved documents.
- **Output Tokens:** Text generated by the model as its response.

Input tokens are often greater than output tokens in RAG applications because retrieved document chunks are included in the prompt.

## 3. Cost Estimation Formula

The general formula for estimating cloud LLM usage cost is:

Cost = Users × Queries per Day × Tokens per Query × Days × Price per Token

For separate input and output prices, use:

Total Cost = Input Token Cost + Output Token Cost

Input Token Cost = Total Input Tokens × Input Price per Token

Output Token Cost = Total Output Tokens × Output Price per Token

## 4. Example Usage Estimation

Assume the following hypothetical usage:

| Parameter | Value |
|---|---:|
| Number of employees | 100 |
| Queries per employee per day | 10 |
| Average input tokens per query | 1,000 |
| Average output tokens per query | 300 |
| Number of working days | 30 |

### Monthly Token Calculation

Total Queries = 100 × 10 × 30 = 30,000 queries

Total Input Tokens = 30,000 × 1,000 = 30,000,000 tokens

Total Output Tokens = 30,000 × 300 = 9,000,000 tokens

Total Tokens = 39,000,000 tokens

## 5. Cloud vs Local Inference

### Cloud-Based LLM

- Requires an external API service.
- Usage is generally billed according to input and output tokens.
- Costs increase as the number of users and queries increases.
- Company data may be transmitted outside the organization's infrastructure, subject to provider terms and configuration.

### Local LLM Using Ollama

- Runs the model on company-controlled hardware.
- Does not require per-token API charges.
- Avoids sending prompts to an external LLM API when configured for local inference.
- Requires hardware, electricity, maintenance and storage.

## 6. Token Economics Comparison

| Factor | Cloud LLM | Local Ollama |
|---|---|---|
| API token charges | Usually applicable | No per-token API charge |
| Hardware | Provider-managed | Company-managed |
| Scalability | Depends on provider limits and pricing | Depends on available hardware |
| Data control | Depends on provider and agreement | Greater local control |
| Operating cost | Usage-based API charges | Hardware, power and maintenance |

## 7. Important Economic Considerations

- Monitor average input and output tokens per query.
- Limit unnecessary retrieved document chunks.
- Set maximum agent execution steps.
- Measure hardware utilization during local inference.
- Consider electricity, maintenance and hardware depreciation when estimating local operating costs.

## 8. Conclusion

Token budgeting helps estimate the resources required to operate an AI assistant. Local inference through Ollama eliminates per-token API billing, making usage costs more predictable. However, local infrastructure still has hardware and operating costs that must be considered.
